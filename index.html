1

What is deep learning?

Where it sits within AI, why learning from data beats writing rules, and the handful of parts every deep learning system shares.

Why should engineers care?

Deep learning in engineering practice

  • Autonomous vehicles: perception from camera and lidar, control
  • Structural health monitoring: crack detection in inspection images
  • Energy systems: load forecasting and optimisation
  • Manufacturing: visual quality control, predictive maintenance
  • Materials science: property prediction and design

Not magic: a systematic tool

Deep learning is a way of fitting very flexible functions to data. It is useful for

  • extracting patterns from high-dimensional data,
  • automating complex decisions,
  • problems too complex for hand-written rules.

Today's goal: understand how it works well enough to build one yourself by the end of the session.

Three nested ideas

Artificial intelligence 1956 onwards

The effort to automate intellectual tasks normally performed by people. Includes hand-written rules and search.

Machine learning 1990s onwards

Systems that are trained on examples rather than explicitly programmed.

Deep learning 2010s onwards

Machine learning with many successive layers of increasingly useful representations.

The shift: from programming explicit rules, to learning rules from data, to learning hierarchical representations automatically. (Deep Blue itself was brute-force search, not learning.)

Why symbolic AI failed at scale

The expert systems approach (1970s and 1980s)

Encode expert knowledge as formal rules, for example in medical diagnosis: if symptom A and symptom B, then disease X.

What went wrong

  • Knowledge bottleneck: far too many rules to write down
  • Brittleness: edge cases break the rule set
  • No learning: cannot improve from experience
  • Noise: real-world data is ambiguous and messy

Engineering analogy

Design a controller by writing a rule for every combination of sensor readings. With ten sensors and a hundred levels each, that is \(10^{20}\) cases.

The way out

Let the system discover the rules from examples. That is machine learning.

In machine learning the rules are the output, not the input. We supply examples with their answers; training finds the rules, stored as numbers called weights. The trained rules are then applied to new data, just like a classical program.

Example: is this manufactured part defective?

Classical programming

  1. Write rules: if edge roughness > threshold, if colour deviation > limit, if symmetry score < bound …
  2. There are thousands of defect types.
  3. Rules are brittle and hard to maintain.
  4. A change of lighting or camera angle breaks them.

Machine learning

  1. Collect 10,000 labelled images: 5,000 defective, 5,000 acceptable.
  2. Train a model on them.
  3. The model discovers the relevant visual features and the decision boundary, and copes with variation in lighting and angle when the training images include it.

Machine learning scales where rule-based systems fail, as long as you have representative data.

Three ingredients of machine learning

1. Input data

Images, sensor readings, text. Must be representative of the problem; more data usually helps.

Self-driving: camera frames.

2. Expected outputs

Labels for classification (defective or acceptable), values for regression (load, stress, temperature).

Self-driving: a box drawn around each pedestrian.

3. A measure of error

A loss function scoring how far predictions are from the expected outputs. Training adjusts the model to make it small.

Regression example: \( \text{MSE} = \frac{1}{n}\sum_i (y_i - \hat y_i)^2 \)

Learning = automatically searching for a better representation of the input data, guided by the feedback from the loss.

Representations: the heart of machine learning

A representation is a different way of looking at the same data that makes something useful explicit.

  • Colour: RGB (255, 128, 0) suits hardware; HSV (30°, 100%, 100%) makes hue and brightness explicit.
  • Signals: the FFT moves from time to frequency, making periodic patterns explicit.

On the right, no straight line separates the two classes in \((x, y)\). In polar coordinates \((\theta, r)\) one threshold on \(r\) does.

A deep network learns transformations like this one, layer by layer, instead of us choosing them.

What does "deep" mean?

"Deep" refers to the number of successive layers, not to deep understanding. Each layer applies a simple transformation and passes a refined representation on.

Like a multi-stage filter in signal processing, each stage strips away what is irrelevant and keeps what matters.
Shallow learning: 1 or 2 layers. Modern deep networks: tens to hundreds of layers.

Weights, loss and the training loop

Weights

Each layer computes \( y = f(\textcolor{#68246D}{W}x + \textcolor{#68246D}{b}) \). The weights \(\textcolor{#68246D}{W}, \textcolor{#68246D}{b}\) start as small random numbers; training tunes them, like the parameters of a filter, but millions of them.

Loss

One number measuring how wrong the predictions are. It must be differentiable.

Update

\( w_{\text{new}} = w_{\text{old}} - \eta \, \textcolor{#17707F}{\nabla_w L} \)

\(\eta\) is the learning rate. The loop repeats thousands to millions of times.

Why deep learning took over

Simplicity

Classical ML spent most of its effort on hand-designed features (SIFT, HOG, MFCC). Deep networks learn features from raw pixels or waveforms, optimised end to end for the task.

Scalability

Training is mostly matrix multiplication, which GPUs parallelise across thousands of cores. Performance keeps improving with more data, parameters and compute: scaling laws.

Versatility

Learn once, reuse many times. Pre-train on a large general dataset, then fine-tune on a small one: transfer learning, and at the extreme, foundation models adapted by prompting.

For engineers, transfer learning matters most: a crack detector can start from a network pre-trained on a million everyday photos and be fine-tuned on a few hundred inspection images.

A measured view: skill is not intelligence

What today's systems do well

  • Automate tasks well covered by their training data
  • Interpolate within the training distribution
  • Handle well-defined problems at scale
  • Assist human experts

Where they still struggle

  • Truly novel situations, far from the training data
  • Reliable explanations of their decisions
  • Learning a new task from very little data
Chollet's definition: intelligence is the ability to adapt to novel situations using limited experience. By that yardstick, current deep learning is mostly skill, and an engineer's job is to know where the training data ends.
2

A neural network by hand

The anatomy of a network, the functions inside a neuron, how loss and gradients drive learning, and one full training iteration worked through with numbers.

Network architecture

Input layer: receives the raw features and passes them in.

Hidden layers: combine their inputs through weighted connections.

Output layer: produces the prediction.

Information flows one way, input to output, with no feedback connections: a feedforward network.

The number of layers and neurons per layer is the architecture. It sets how complex a mapping the network can learn.

Inside a single neuron

Each neuron computes a weighted sum \( a = \sum_i \textcolor{#68246D}{w_i} x_i + \textcolor{#68246D}{b} \) and passes it through a transfer function, \( y = f(a) \). Drag the weights and switch the function.

Common transfer (activation) functions

Linear \( f(x) = x \)
Output layer for regression, where any real value is allowed.
Sigmoid \( f(x) = \dfrac{1}{1 + e^{-x}} \)
Squashes to (0, 1), read as a probability in binary classification.
ReLU \( f(x) = \max(0, x) \)
The default for hidden layers: cheap and less prone to vanishing gradients.
Without a nonlinear function, a stack of layers collapses into one linear map, however deep it is. Nonlinearity is what makes depth useful.

Loss functions: scoring the predictions

Regression

\[ \text{MSE} = \frac{1}{N}\sum_{k=1}^{N} (y_k - \hat y_k)^2 \qquad \text{RMSE} = \sqrt{\text{MSE}} \]

MSE is smooth and punishes large errors heavily, so normalising widely spread data helps. RMSE is in the units of the output, handy for reporting.

Classification: cross-entropy

\[ E = -\sum_{i=1}^{C} y_i \log \hat y_i \]

\(y\) is the one-hot true label, \(\hat y_i\) the predicted probability of class \(i\). Only the true class term survives, so \(E = -\log(\text{probability given to the right answer})\).

Confident and wrong is punished hardest. That is why cross-entropy pushes a classifier to be both right and appropriately sure.

Gradient descent: walking downhill

The derivative is the local slope: near \(w\), \( L(w + \epsilon) \approx L(w) + L'(w)\,\epsilon \).

  • If \(L'(w) > 0\), move \(w\) left.
  • If \(L'(w) < 0\), move \(w\) right.

\[ w \leftarrow w - \eta\,\textcolor{#17707F}{L'(w)} \]

With many weights the derivative becomes the gradient \(\nabla_w L\), which points uphill most steeply; we step the other way.

Try each learning rate: too small crawls, too large oscillates or diverges.

Backpropagation: the chain rule at work

A network is a composition of functions, so for one neuron with pre-activation \(a\) and output \(y\):

\[ \frac{\partial E}{\partial w} = \textcolor{#B83A2E}{\frac{\partial E}{\partial y}} \cdot \frac{\partial y}{\partial a} \cdot \frac{\partial a}{\partial w} \]

  • how the error changes with the output, from the loss,
  • how the output changes with the weighted sum: \(f'(a)\),
  • how the weighted sum changes with the weight: the input \(x\).

The error is computed at the output and passed backwards, layer by layer, reusing each layer's result. One backward pass gives every gradient, at about the cost of a forward pass. Frameworks such as TensorFlow and PyTorch do this automatically.

Step 4: gradients by the chain rule

For one sample, \(E = e^2\) and \(e = \hat y - Y\), so

\[ \frac{\partial E}{\partial w_{11}} = \textcolor{#B83A2E}{\frac{\partial E}{\partial \hat y}} \cdot \frac{\partial \hat y}{\partial w_{11}} = \textcolor{#B83A2E}{2e} \cdot X_1 \]

and likewise \( \partial E / \partial w_{21} = 2e\,X_2 \).

Average over the four samples (the MSE is an average):

\[ \textcolor{#17707F}{\frac{\partial\,\text{MSE}}{\partial w_{11}} = -0.1457} \qquad \textcolor{#17707F}{\frac{\partial\,\text{MSE}}{\partial w_{21}} = -0.0901} \]

The loss landscape of this example

The same example in NumPy


import numpy as np

# four samples: columns are X1 and X2
X = np.array([[0.1, 0.01],
              [0.3, 0.09],
              [0.6, 0.36],
              [0.7, 0.49]])
Y = np.array([0.20, 0.25, 0.40, 0.70])

w = np.array([0.5, 0.1])    # Step 1: initial weights
lr = 0.3                     # learning rate (alpha)

for it in range(2):
    y_hat = X @ w            # Step 2: forward pass, linear neuron
    e = y_hat - Y            # Step 3: error per sample
    mse = np.mean(e ** 2)
    # Step 4: dMSE/dw, averaged over samples
    grad = np.mean(2 * e[:, None] * X, axis=0)
    # Step 5: gradient descent update
    w = w - lr * grad
    print(f"iteration {it}: MSE={mse:.4f}  w={np.round(w, 4)}")
      

iteration 0: MSE=0.0313  w=[0.5437 0.127 ]
iteration 1: MSE=0.0234  w=[0.5788 0.1487]

X @ w does all four forward passes at once as a matrix product: shape (4, 2) times (2,) gives (4,).

e[:, None] * X uses broadcasting: (4, 1) times (4, 2) gives (4, 2).

Vectorised code like this is exactly what GPUs accelerate.

A first classifier: MNIST

Same loop, bigger numbers: 60,000 images, 407,050 weights, ten classes. Five short Keras calls.

The problem: read a handwritten digit

Input: a 28 × 28 greyscale image, values 0 to 255.
Output: one of ten classes, 0 to 9.

60,000 training images and 10,000 test images, written by hundreds of people. The "hello world" of deep learning, and the same shape of problem as visual inspection: camera image in, class out.

Terms: a sample is one image; a class is a category (0 to 9); a label is the class attached to a sample.

Tensors: how the data is stored

A tensor is a multidimensional array. Its rank is the number of axes; its shape is the length along each axis.

Scalar

rank 0, shape ()

Vector

rank 1, shape (6,)

Matrix

rank 2, shape (5, 5)

Rank-3 tensor

rank 3, shape (3, 5, 5)
train_images is a rank-3 tensor of shape (60000, 28, 28) and type uint8: 60,000 matrices of 28 × 28 integers. The first axis is the samples axis; later we cut it into batches.

Prepare the data


# Reshape: flatten each 28x28 image to a 784-vector

# Normalise: integers 0-255 -> floats in [0, 1]

Reshape

(60000, 28, 28) → (60000, 784). A dense layer expects a vector per sample; row by row, each image becomes 784 numbers, as on the drawing pad.

Why normalise?

  • Networks train best on small inputs
  • Avoids large, unstable gradient updates
  • Converges faster

Standard practice: scale inputs to [0, 1] or [−1, 1].

Dense means fully connected: every unit sees every unit of the previous layer through its own weight.

ReLU inside, softmax at the output

ReLU in the hidden layer, \( \max(0, x) \), supplies the nonlinearity.

Softmax turns the ten raw output scores (logits \(z\)) into a probability distribution:

\[ \hat y_i = \frac{e^{z_i}}{\sum_{j=0}^{9} e^{z_j}} \]

Every output lies between 0 and 1 and they sum to 1. The prediction is the class with the largest probability.

Exponentiating then normalising exaggerates the gap between the top score and the rest.

Compile: choose how to learn


model.compile(
    optimizer="adam",
    loss="sparse_categorical_crossentropy",
    metrics=["accuracy"],
)

Optimizer

How weights are updated from gradients. Adam: adaptive moment estimation, a robust default.

Loss

Cross-entropy for classification. Sparse means the labels are integers (7), not one-hot vectors.

Metrics

What we report to people. Accuracy is readable, but is not differentiable, so it cannot be the loss.

Fit: epochs and mini-batches


model.fit(train_images, train_labels, epochs=5, batch_size=128)

Each batch of 128 images gives one gradient estimate and one weight update: mini-batch stochastic gradient descent. An epoch is one full pass over the 60,000 images: 469 batches (the last holds 96).

Mind the gap

Better on training data than on unseen data: mild overfitting. The model has partly memorised its training set. Measuring and controlling this gap is a central theme of the module.

What fit() does under the hood


import tensorflow as tf

loss_fn = keras.losses.SparseCategoricalCrossentropy()
optimizer = keras.optimizers.Adam()
dataset = tf.data.Dataset.from_tensor_slices(
    (train_images, train_labels)).shuffle(60000).batch(128)

for epoch in range(5):
    for x_batch, y_batch in dataset:      # 469 batches per epoch
        with tf.GradientTape() as tape:
            y_pred = model(x_batch, training=True)
            loss = loss_fn(y_batch, y_pred)
        grads = tape.gradient(loss, model.trainable_weights)
        optimizer.apply_gradients(zip(grads, model.trainable_weights))
  1. Batch: draw 128 samples and their targets
  2. Forward pass: \(\hat y = \text{model}(x)\)
  3. Loss: \(L = \text{loss}(y, \hat y)\)
  4. Backpropagation: \(\nabla_W L\), recorded by the tape
  5. Update: \(W \leftarrow W - \eta \nabla_W L\) (Adam refines this)

The same five steps as the hand-worked example. Only the scale has changed: 407,050 weights instead of 2.

Optimisers: beyond plain gradient descent

SGD

\( w \leftarrow w - \eta \nabla_w L \)

Simple, one fixed learning rate. Crawls along long narrow valleys and can stall in shallow local minima.

Momentum

\( v_t = \mu v_{t-1} - \eta \nabla_w L \)
\( w_t = w_{t-1} + v_t \)

A ball rolling downhill: velocity accumulates, so it speeds along valleys, damps oscillation and rolls through small dips. Typically \(\mu = 0.9\).

Adam

Momentum plus a separate, adaptive step size for every parameter, scaled by the recent size of its gradients. Works well with little tuning: the default choice for most problems.

Go back to the loss-landscape slide of the worked example and switch on momentum: the long valley is exactly where it helps.

The complete script


import keras
from keras import layers
from keras.datasets import mnist

# 1. Load
(train_images, train_labels), (test_images, test_labels) = mnist.load_data()

# 2. Prepare: flatten and scale to [0, 1]
train_images = train_images.reshape((60000, 28 * 28)).astype("float32") / 255
test_images = test_images.reshape((10000, 28 * 28)).astype("float32") / 255

# 3. Build
model = keras.Sequential([
    layers.Dense(512, activation="relu"),
    layers.Dense(10, activation="softmax"),
])

# 4. Compile
model.compile(optimizer="adam",
              loss="sparse_categorical_crossentropy",
              metrics=["accuracy"])

# 5. Train
model.fit(train_images, train_labels, epochs=5, batch_size=128)

# 6. Evaluate on unseen data
test_loss, test_acc = model.evaluate(test_images, test_labels)
print(f"test accuracy: {test_acc:.3f}")

Key takeaways

  1. AI ⊃ ML ⊃ DL. Deep learning is machine learning with many successive layers of learned representations.
  2. Machine learning inverts programming: from data and answers it produces the rules, stored as weights.
  3. One loop does all the learning: forward pass, loss, backpropagation (the chain rule), weight update \( w \leftarrow w - \eta \nabla_w L \).
  4. The hand-worked neuron and the MNIST network run the same loop; only the number of weights differs, 2 versus 407,050.
  5. Watch the gap between training and test performance: that is what generalisation means in practice.
