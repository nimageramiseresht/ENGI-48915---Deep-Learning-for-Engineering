Image segmentation

CNNs that classify every pixel, and a model that can segment anything

  1. 1Image segmentation
  2. 2Recurrent neural networks
  3. 3Transfer learning

From boxes to pixels

  • Week 3 introduced semantic and instance segmentation. Panoptic is the union: every pixel gets a class, and countable "things" also get an instance number, while "stuff" such as sky and ground does not.

Segmentation is classification, at every pixel

A classifier outputs one probability vector per image. A segmentation network outputs one per pixel: a tensor of shape \(H \times W \times C\), with a softmax over the \(C\) classes at each location.

The target is a mask: an image of the same size whose pixel values are class labels. The loss is the cross-entropy of Week 2, averaged over all pixels:

\[ \mathcal{L} = -\frac{1}{HW}\sum_{i=1}^{H}\sum_{j=1}^{W}\;\sum_{c=1}^{C} y_{ijc}\,\log \hat{y}_{ijc} \]

Example: the Oxford-IIIT Pets masks have 3 classes per pixel: pet, background, and the outline between them.

  • Nothing new in the loss: it is the same categorical cross-entropy, applied H × W times.
  • The hard part is the architecture: the output must have the input's full resolution.

The encoder-decoder architecture

Encoder: compress

Strided convolutions halve height and width three times while the channels grow: the network learns what is in the image.

Decoder: expand

Transposed convolutions double height and width three times, turning features back into a full-resolution map: where each thing is.

Symmetry

Each downsampling step has a matching upsampling step, so the output is exactly 200 × 200, one prediction per input pixel.

  • The encoder is the CNN of Week 3 without the classification head; the decoder mirrors it.
  • The output has as many channels as classes: 3 for the pets example.

Why strided convolutions, not max pooling

Both halve the size of a feature map. But max pooling only reports the largest value in each window, not where it was. For classification that is helpful; for segmentation, where location is the answer, it throws information away.

A strided convolution computes a learned weighted sum instead. Its weights differ by position within the window, so the output still depends on where the feature was.

Upsampling with a transposed convolution

filter:

Step 1, stretch: put a zero between every value (stride 2). Step 2, filter: slide a 3 × 3 kernel over the stretched map, exactly as in an ordinary convolution. The kernel decides how the gaps are filled.

For example \(\text{out}[0,0] = w_5\,a\), \(\;\text{out}[0,1] = w_4\,a + w_6\,b\), \(\;\text{out}[1,1] = w_1 a + w_3 b + w_7 c + w_9 d\). With smooth weights this is bilinear interpolation; in training, the network learns its own.

  • Step through the 16 positions: each output is a weighted sum of whichever original values the kernel covers.
  • Switch to "a learned one": same mechanics, different interpolation. Keras: Conv2DTranspose(filters, 3, strides=2, padding="same"). UpSampling2D is the fixed, parameter-free alternative.
  • Known side effect: transposed convolutions can leave checkerboard artefacts; resize-then-convolve avoids them (Odena et al., 2016).

The segmentation model in Keras

def get_model(img_size=(200, 200), num_classes=3):
    inputs = keras.Input(shape=img_size + (3,))
    x = layers.Rescaling(1.0 / 255)(inputs)
    for f in [64, 128, 256]:            # encoder: 200 -> 25
        x = layers.Conv2D(f, 3, strides=2, padding="same",
                          activation="relu")(x)
        x = layers.Conv2D(f, 3, padding="same", activation="relu")(x)
    for f in [256, 128, 64]:            # decoder: 25 -> 200
        x = layers.Conv2DTranspose(f, 3, padding="same",
                                   activation="relu")(x)
        x = layers.Conv2DTranspose(f, 3, strides=2, padding="same",
                                   activation="relu")(x)
    outputs = layers.Conv2D(num_classes, 3, padding="same",
                            activation="softmax")(x)   # per pixel
    return keras.Model(inputs, outputs)

model = get_model()
model.compile(optimizer="rmsprop",
              loss="sparse_categorical_crossentropy")

padding="same" keeps sizes exact: without it every 3 × 3 convolution trims 2 pixels and the decoder would not land back on 200 × 200.

strides=2 on every other layer does the halving and doubling.

The output is 200 × 200 × 3. Masks hold integer labels, so the loss is sparse_categorical_crossentropy, applied at every pixel.

About 2.9 million parameters. Checked: the shapes run 100, 50, 25, then 50, 100, 200.

  • This is the Lecture 7 model written as two loops; the layers are identical.
  • Keras subtracts nothing from the masks; Oxford Pets labels are 1 to 3, so subtract 1 when loading them.

U-Net: skip connections bring back the detail

The encoder's 25 × 25 bottleneck knows what is in the image, but fine detail, such as the exact edge of a crack, has been squeezed out. U-Net (Ronneberger et al., 2015) copies each encoder map across to the decoder layer of the same size and concatenates them.

e1 = layers.Conv2D(64, 3, strides=2, padding="same",
        activation="relu")(inputs)          # 100x100
...
d1 = layers.Conv2DTranspose(64, 3, strides=2,  # 100x100
        padding="same", activation="relu")(d2)
d1 = layers.Concatenate()([d1, e1])   # 64 + 64 channels

The decoder then sees both: deep meaning from below, sharp detail from across. U-Net was designed for biomedical images and remains a standard in medical and inspection work.

  • This answers the "additional challenge" of the Lecture 7 exercises: skip connections recover boundaries lost in downsampling.
  • Same fusion idea as YOLO's neck last week: concatenate channels, let a convolution mix them.

Measuring a mask: IoU and Dice

\[ \mathrm{IoU} = \frac{|A \cap B|}{|A \cup B|} \qquad \mathrm{Dice} = \frac{2\,|A \cap B|}{|A| + |B|} \]

The same IoU as for boxes in Week 3, now counting pixels. Dice weights the overlap twice; the two are linked by \(\mathrm{Dice} = 2\,\mathrm{IoU} / (1 + \mathrm{IoU})\), so they rank models alike, but Dice reads higher.

Avoid pixel accuracy

If 95% of the image is background, predicting "background" everywhere scores 95% pixel accuracy, and IoU 0 for the defect. Report IoU or Dice per class, and their mean.

Dice is the usual choice in medical imaging, IoU in autonomous driving.

  • Move the prediction away: IoU and Dice fall together, Dice always above IoU (equal only at 0 and 1).
  • Class imbalance is the main segmentation pitfall; weighted losses or Dice-based losses help (Week 3's focal loss is another option).

Segment Anything: a foundation model for masks

The Segment Anything Model (SAM; Kirillov et al., 2023, Meta AI) is not trained for a fixed set of classes. You give it a prompt, a point or a box, and it returns the mask of whatever is there.

  • trained on SA-1B: 11 million images and 1.1 billion masks, about 100 per image
  • works on objects it has never seen, with no fine-tuning: zero-shot
  • versions: SAM (2023), SAM 2 for images and video (2024), and the small MobileSAM

The pattern behind it: a very large model, pretrained once, that adapts to new tasks through prompting rather than retraining. Section 3 returns to this idea.

Inside SAM

Image encoder

A Vision Transformer turns the 1024 × 1024 image into a 64 × 64 × 256 embedding. It is the heavy part, and it runs once per image.

Prompt encoder

Turns each point (with label 1 for foreground, 0 for background) or box (two corners) into embedding vectors.

Mask decoder

A light network that combines the two and outputs masks, each with a predicted IoU as its confidence. It takes milliseconds, so prompts feel interactive.

  • Because the decoder is cheap, the same image embedding serves many prompts: this is what makes click-to-segment tools fast.
  • Training: random masks from SA-1B, prompts sampled from them (a point inside, or the box around), all three parts trained together end to end.

Try it: prompt the model

A simulation of what SAM returns. One point is often ambiguous (part, object, or group?), so SAM can return several candidates, each with a score.

  • Click a worker's helmet: the candidates are the helmet, the worker, and both workers. Pick each one. Then try a box around the excavator: a box is less ambiguous, so one mask is usually enough.
  • In Ultralytics, multiple candidates are off by default; the predictor returns the best mask per prompt.

Time series in engineering

Much engineering data arrives as a sequence of measurements in time: vibration from a bearing, temperature in a building, strain on a bridge, power demand on a grid, traffic at a junction.

What makes sequences different

  • order matters: shuffle the readings and the meaning is gone
  • context matters: today's value depends on what came before
  • length varies: a recording may be 10 seconds or 10 hours
ModelHow it treats a sequence
MLPa fixed-length window, flattened: no notion of order
1-D CNNlocal patterns with a kernel sliding in time; limited reach
RNNreads one step at a time and carries a memory forward

Typical tasks: forecasting the next values (regression), classifying a whole sequence (fault or normal), and detecting anomalies.

  • Connect to Week 2: forecasting is regression, fault detection is classification. Only the input changes, from a vector to a sequence.

From a signal to training examples

Slide a window along the signal: the values inside are one input, the value just after it is the target. Every position gives one training example.

window = 24                     # past readings
X = np.stack([signal[i:i + window]
              for i in range(len(signal) - window)])
y = signal[window:]             # the next reading
X = X[..., None]                # add a feature axis
print(X.shape)  # (samples, timesteps, features)

Recurrent layers expect inputs of shape (samples, timesteps, features). With several sensors, features is the number of sensors.

Split by time, never at random: train on the past, validate on the future (Week 2).

  • Drag the position: the window and its target move together. A larger window gives the model more context, and the gradient problem later shows why that is not free.
  • keras.utils.timeseries_dataset_from_array builds the same windows without holding them all in memory.

The recurrent cell

At every time step the cell combines the new input \(\mathbf{x}_t\) with its own previous output, the hidden state \(\mathbf{h}_{t-1}\):

\[ \mathbf{h}_t = \tanh\big(W_x\,\mathbf{x}_t + W_h\,\mathbf{h}_{t-1} + \mathbf{b}\big) \]

After the last step, a Dense layer reads the final state: \(\hat{y} = W_y\,\mathbf{h}_T + c\). The state starts at \(\mathbf{h}_0 = \mathbf{0}\).

The same weights at every step

\(W_x\), \(W_h\) and \(\mathbf{b}\) are reused at every time step, just as a CNN reuses one kernel at every position. Sharing in time instead of in space, so the cell handles any sequence length.

  • The loop on the left and the chain on the right are the same network: "unrolling" just draws one copy per time step.
  • h_t summarises everything seen so far; that is the memory.

Try it: run an RNN by hand

A one-unit RNN with \(w_x = 1\), \(w_h = 0.8\), \(b = 0\):

\[ h_t = \tanh(1 \cdot x_t + 0.8\, h_{t-1}) \]

  • Step through: the first input is 1, the rest are small, yet h stays non-zero for several steps: the cell remembers the spike.
  • Set w_h to 0: no memory, h just follows x. Set it to 1.5: the memory lingers far longer. w_h is the knob that will cause trouble on the gradient slides.

Parameters: \(W_x\) has \(n \cdot u\), \(W_h\) has \(u \cdot u\), and the bias \(u\):

\[ u\,(u + n + 1) \]

For 32 units on one sensor: 32 × (32 + 1 + 1) = 1,088, whatever the window length.

return_sequences=True outputs \(\mathbf{h}_t\) at every step, shape (timesteps, units), so another recurrent layer can read it.

Compare with the Week 2 baseline idea: "tomorrow = today" is the forecast to beat.

  • Parameter counts checked in Keras. The count does not grow with the window: same weights at every step.

Training: backpropagation through time

Unrolled, an RNN is just a deep network with one layer per time step, all sharing the same weights. Training is ordinary backpropagation on that unrolled graph: backpropagation through time.

For the loss to learn from an early input \(\mathbf{x}_k\), its gradient must travel back through every later step. By the chain rule:

\[ \frac{\partial \mathcal{L}}{\partial \mathbf{h}_k} = \frac{\partial \mathcal{L}}{\partial \mathbf{h}_T}\;\prod_{t=k+1}^{T}\frac{\partial \mathbf{h}_t}{\partial \mathbf{h}_{t-1}} \]

A product of \(T - k\) factors, one per step. The longer the context, the more factors. Everything that follows comes from this product.

  • Ask: what happens to a product of 100 numbers that are each a bit bigger than 1? A bit smaller than 1? Then show the next slide.

Why long sequences break the gradient

Take one unit, and for clarity a linear activation: \(h_t = w\,h_{t-1} + u\,x_t\). Each factor in the product is then the same number:

\[ \frac{\partial h_t}{\partial h_{t-1}} = w \quad\Rightarrow\quad \frac{\partial h_T}{\partial h_0} = \prod_{t=1}^{T} w = w^{T} \]

  • \(|w| > 1\): \(|w|^T \to \infty\) as \(T\) grows: the gradient explodes
  • \(|w| < 1\): \(|w|^T \to 0\): the gradient vanishes
  • only \(|w| = 1\) exactly is stable, and training will not keep it there

For any \(|w| > 1\), however close to 1, a long enough context makes the gradient blow up: \(1.01^{1000} \approx 21{,}000\).

With tanh, each factor becomes \(w\,(1 - h_t^2)\). Since \(1 - h_t^2 \le 1\), tanh can only shrink the factors: vanishing gets even more likely, and explosion happens whenever the units stay in tanh's near-linear range.

  • Write w^T on the board and evaluate one entry live: 1.1^100 = e^(100 ln 1.1) = e^9.53 ≈ 13,800.
  • The point the slide must land: the problem is not the size of w but the length of the product. Long context alone is enough.

The same result for real, many-unit RNNs

With a vector state, each factor is a matrix, the Jacobian of one step:

\[ \frac{\partial \mathbf{h}_t}{\partial \mathbf{h}_{t-1}} = \mathrm{diag}\big(\tanh'(\mathbf{a}_t)\big)\,W_h \]

Ignore the tanh for a moment. The product is then \(W_h^{\,T}\). Write \(W_h = Q \Lambda Q^{-1}\) with eigenvalues \(\lambda_i\):

\[ W_h^{\,T} = Q\,\Lambda^{T} Q^{-1}, \qquad \Lambda^{T} = \mathrm{diag}\big(\lambda_1^{T}, \dots, \lambda_n^{T}\big) \]

Every eigenvalue is raised to the power \(T\): exactly the scalar case, once per direction.

The rule

  • largest \(|\lambda_i| > 1\): some direction explodes
  • all \(|\lambda_i| < 1\): every direction vanishes

With tanh included, \(\big\|\partial \mathbf{h}_T/\partial \mathbf{h}_k\big\| \le \big(\gamma\,\sigma_{\max}(W_h)\big)^{T-k}\), where \(\gamma \le 1\) bounds tanh's slope (Pascanu et al., 2013).

First analysed by Hochreiter (1991) and Bengio et al. (1994).

  • The eigen-decomposition makes the scalar argument general: in each eigen-direction the gradient is multiplied by lambda at every step.
  • σ_max is the largest singular value; for a symmetric W it equals the largest |λ|.

Try it: how far back does the gradient reach?

The curve is \(|w|^{k}\): how strongly the loss at the end can "feel" an input \(k\) steps earlier. The grey band marks a usable range; outside it, training either diverges or learns nothing from the past.

  • Start at w = 1.05 and drag the steps: after about 300 steps the gradient passes a million. Then w = 0.95: below one millionth by about 270 steps.
  • Ask: what w would be safe for 500 steps? Only values extremely close to 1, which training cannot guarantee.

What it means in practice

Exploding gradients

Huge updates throw the weights far away: the loss jumps or becomes NaN.

Fix: gradient clipping, rescaling the gradient whenever its norm exceeds a limit:

keras.optimizers.Adam(1e-3, clipnorm=1.0)

Clipping treats the symptom: the direction is kept, the size capped.

Vanishing gradients

Training runs, but the early steps receive almost no gradient, so the model only learns from the last few readings. It cannot connect a cause to an effect many steps later.

Fix: give the gradient a path that does not multiply by \(W_h\) at every step. That path is the LSTM's cell state.

Clipping handles explosion. Vanishing needs a different architecture: gated recurrent units, the LSTM and the GRU.

  • Engineering example of a long dependency: a pump's temperature rise today caused by a valve change hours of readings ago.

LSTM: a memory cell with gates

Long short-term memory (Hochreiter and Schmidhuber, 1997) adds a cell state \(\mathbf{c}_t\), a conveyor belt running through time, and three sigmoid gates between 0 and 1 that decide what to forget, write and read:

\[ \begin{aligned} \mathbf{f}_t &= \sigma(W_f[\mathbf{h}_{t-1}, \mathbf{x}_t] + \mathbf{b}_f) && \text{forget} \\ \mathbf{i}_t &= \sigma(W_i[\mathbf{h}_{t-1}, \mathbf{x}_t] + \mathbf{b}_i) && \text{input} \\ \mathbf{o}_t &= \sigma(W_o[\mathbf{h}_{t-1}, \mathbf{x}_t] + \mathbf{b}_o) && \text{output} \\ \tilde{\mathbf{c}}_t &= \tanh(W_c[\mathbf{h}_{t-1}, \mathbf{x}_t] + \mathbf{b}_c) && \text{candidate} \\ \mathbf{c}_t &= \mathbf{f}_t \odot \mathbf{c}_{t-1} + \mathbf{i}_t \odot \tilde{\mathbf{c}}_t \\ \mathbf{h}_t &= \mathbf{o}_t \odot \tanh(\mathbf{c}_t) \end{aligned} \]

  • Read the cell-state line: keep a fraction f of the old memory, add a fraction i of new information. Multiplication by gates, addition of new content.
  • [h, x] means the two vectors stacked; ⊙ is element-wise multiplication.

Why the LSTM gradient survives

Follow the gradient along the cell state. From \(\mathbf{c}_t = \mathbf{f}_t \odot \mathbf{c}_{t-1} + \mathbf{i}_t \odot \tilde{\mathbf{c}}_t\):

\[ \frac{\partial \mathbf{c}_t}{\partial \mathbf{c}_{t-1}} = \mathrm{diag}(\mathbf{f}_t) \quad\Rightarrow\quad \frac{\partial \mathbf{c}_T}{\partial \mathbf{c}_k} = \prod_{t=k+1}^{T} \mathrm{diag}(\mathbf{f}_t) \]

  • no \(W_h\) in the product: nothing gets raised to the power \(T\)
  • each factor is a forget gate in (0, 1), and the network learns to keep it near 1 for information worth remembering
  • it can never exceed 1, so this path cannot explode

Keras initialises the forget-gate bias to 1 (unit_forget_bias=True), so memories start out kept.

  • Treating the gates as constants is a simplification (they depend on h), but it is the path that matters: Hochreiter and Schmidhuber called it the constant error carousel.
  • With w = 0.9 and f = 0.99, after 100 steps the RNN keeps 0.003% of the gradient, the LSTM 37%.

GRU (Cho et al., 2014) merges the forget and input gates and drops the separate cell state: fewer parameters, often similar accuracy.

Always compare against a naive forecast first; on short, noisy signals it can be surprisingly hard to beat.

  • Parameter counts checked in Keras (the GRU count includes Keras's default reset_after biases).
  • Since around 2018 transformers have taken over long sequences in language, but LSTMs and GRUs remain common for sensor data: small, fast, and good with modest data.

Why transfer learning?

The data problem

Deep networks need many labelled examples; engineering datasets are often small, and labels cost specialists' time.

The compute problem

Training large models from scratch takes days of GPU time, with a real energy cost.

Key idea: features learned on one task, such as edges, textures and shapes from millions of photos, are useful for many others.

Definition (Pan and Yang, 2010)

Given a source domain \(\mathcal{D}_S\) with task \(\mathcal{T}_S\), and a target domain \(\mathcal{D}_T\) with task \(\mathcal{T}_T\), transfer learning improves the target function \(f_T(\cdot)\) using knowledge from \(\mathcal{D}_S\) and \(\mathcal{T}_S\), where \(\mathcal{D}_S \ne \mathcal{D}_T\) or \(\mathcal{T}_S \ne \mathcal{T}_T\).

A domain is a feature space and its distribution, \(\mathcal{D} = \{\mathcal{X}, P(X)\}\). A task is a label space and a function, \(\mathcal{T} = \{\mathcal{Y}, f\}\) with \(f: \mathcal{X} \to \mathcal{Y}\).

Example: source ImageNet photo classification; target cracks in concrete.

  • You have already used it: YOLOv8 backbones pretrained on COCO (Week 3), SAM trained on SA-1B (today).

The mathematics: a warm start

Ordinary training minimises the empirical risk on the \(n_T\) target examples, starting from random weights:

\[ \min_{\theta_T}\; \frac{1}{n_T}\sum_{i=1}^{n_T} \mathcal{L}\big(f_{\theta_T}(\mathbf{x}_i^T),\, y_i^T\big) \]

Transfer learning keeps the same objective but changes the starting point, to the weights \(\theta_S^*\) already learned on the source:

\[ \theta_T^{(0)} = \theta_S^*, \qquad \theta_T^{(t+1)} = \theta_T^{(t)} - \eta\,\nabla_{\theta_T}\mathcal{L} \]

Gradient descent starts in a region that already captures useful features, so it needs far fewer examples and steps to reach a good minimum.

Illustration: same number of steps, very different end points.

  • Same loss, same optimiser; only θ(0) changes. With little data, a random start overfits long before it reaches a good region; the warm start begins there.

Feature extraction or fine-tuning?

Feature extraction

Freeze the pretrained layers, train only a new head:

\[ \theta_{\text{conv}} = \theta_S^* \;\text{(frozen)}, \qquad \min_{\theta_{\text{head}}} \mathcal{L}\big(f(\mathbf{x}^T), y^T\big) \]

Fine-tuning

Unfreeze some or all layers, with a much smaller learning rate, \(\eta_{\text{fine}} \ll \eta_{\text{scratch}}\), so the pretrained features are adjusted, not erased (catastrophic forgetting). Two refinements:

\[ \mathcal{L}_{\text{total}} = \mathcal{L} + \frac{\lambda}{2}\big\|\theta_T - \theta_S^*\big\|_2^2 \qquad \eta^{(\ell)} = \eta_{\text{base}}\,\alpha^{L-\ell} \]

Left: L2 pull towards the source weights (L2-SP; Li et al., 2018). Right: smaller rates for earlier layers, \(\alpha \in (0, 1)\) (Howard and Ruder, 2018).

Target dataSimilar domainDifferent domain
smallfeature extractionfine-tune the top layers
largefine-tune all layersfine-tune all, or train from scratch

Why it works: early layers learn general edges and textures, deep layers task-specific concepts (Week 3, Section 2). The general layers transfer; the specific ones are retrained.

How far can you transfer? Ben-David et al. (2010): \(\epsilon_T(h) \le \epsilon_S(h) + \tfrac{1}{2}\,d_{\mathcal{H}\Delta\mathcal{H}}(\mathcal{D}_S, \mathcal{D}_T) + \lambda^*\). Target error is bounded by source error plus the distance between the domains.

  • L2-SP: ordinary weight decay pulls towards 0; this pulls towards the pretrained weights instead.
  • Ben-David bound in words: transfer works when the domains are close; X-ray images are far from holiday photos, so expect to fine-tune more.

    weights="imagenet", input_shape=(224, 224, 3), pooling="avg")

base.trainable = False
inputs = keras.Input((224, 224, 3))

# 2. fine-tuning: unfreeze the last stage, tiny learning rate

for layer in base.layers:

model.compile(keras.optimizers.Adam(1e-5), "binary_crossentropy",

Key takeaways

  1. Segmentation is classification at every pixel: an encoder compresses, a decoder with transposed convolutions restores full resolution. Measure it with IoU or Dice, not pixel accuracy.
  2. SAM segments anything from a point or box prompt, with no training: use it through Ultralytics, or to label data for a smaller model.
  3. RNNs carry a hidden state through time, sharing weights across steps as CNNs share them across space.
  4. The gradient back through \(T\) steps is a product of \(T\) factors: \(|w|^T\) explodes for any \(|w| > 1\) and vanishes for \(|w| < 1\). Long context alone causes it. The LSTM's cell state replaces the product of weights with a product of forget gates.
  5. Transfer learning starts from \(\theta_S^*\): freeze and train a head, then fine-tune with a small learning rate.
